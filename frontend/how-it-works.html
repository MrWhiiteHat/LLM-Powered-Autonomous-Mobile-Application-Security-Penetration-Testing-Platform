How It Works: The 10-Phase Pipeline

Each uploaded application flows through a strictly decoupled, 10-phase auditing sequence. Structured JSON contracts ensure resilience, while local LLM reasoning enriches and verifies every flagged vulnerability.

🔄 Sequential Pipeline Orchestration

1. Reconnaissance ➔ 2. Static Dissection ➔ 3. Reverse Engineering ➔ 4. Storage Audit ➔ 5. Network Trust ➔ 6. API Security ➔ 7. Dynamic DBI ➔ 8. RAG Triaging ➔ 9. CVSS Risk ➔ 10. Report Export
PHASE 1

Binary Reconnaissance & Cryptographic Integrity

file_handler.py

Validates binary format (APK/ZIP), computes multi-digest cryptographic hashes (SHA-256, SHA-1, MD5), audits APK signature scheme versions (v1 JAR signing, v2 APK signature scheme, v3 key rotation, and v4 streaming), parses min/target SDK versions, and assigns target size tiers.

Inputs: Raw APK binary file Outputs: Package metadata, certificate fingerprints, cryptographic hashes
PHASE 2

Static Dissection & Manifest Attack Surface

static_analysis.py

Invokes aapt dump xmltree to decompile binary AndroidManifest.xml. Audits 32 dangerous runtime permissions, inspects exported IPC components (Activities, Services, Broadcast Receivers, Content Providers) lacking signature protection, flags android:debuggable="true", and checks ADB backup exposure (android:allowBackup="true").

Inputs: Manifest binary XML Outputs: Permission risk matrix, exported IPC attack surface, build flag warnings
PHASE 3

Reverse Engineering & AST Construction

reverse_engineering.py

Decompiles DEX bytecode into Smali and Java source trees via APKTool 2.9+ and JADX 1.5+. Constructs Abstract Syntax Trees (AST) using javalang, traverses control-flow graphs, extracts REST/WebSocket API endpoints, and scans for high-entropy hardcoded AWS/Firebase/Stripe cloud tokens.

Inputs: DEX bytecode and resources Outputs: Decompiled source tree, AST objects, harvested URLs, hardcoded secrets
PHASE 4

Storage Security & Data Leakage Analysis

storage_analysis.py

Audits application sandboxed storage policies. Detects deprecated MODE_WORLD_READABLE and MODE_WORLD_WRITEABLE flags in SharedPreferences, flags unencrypted SQLite database creations, inspects SQL raw string concatenations for SQL injection, and checks for external storage misuse.

Inputs: Decompiled Java source & asset schemas Outputs: Storage vulnerability records (CWE-312, CWE-922, CWE-89)
PHASE 5

Network Security & Transport Layer Trust

network_analysis.py

Evaluates network_security_config.xml, flags cleartext HTTP transmission allowances (android:usesCleartextTraffic="true"), audits empty custom X509TrustManager implementations that accept all CAs, detects AllowAllHostnameVerifier, and verifies SSL/TLS certificate pinning configurations.

Inputs: Network XML configurations & SSL trust code Outputs: MITM vulnerability findings, TLS trust posture (CWE-295, CWE-319)
PHASE 6

API Security Testing (OWASP API Top 10)

api_testing.py

Probes extracted REST/GraphQL endpoints for Broken Object Level Authorization (BOLA), unauthenticated administrative interfaces, Broken Function Level Authorization (BFLA), server-side request forgery (SSRF), and authorization token exposure in query parameters.

Inputs: Discovered URL routes & parameter schemas Outputs: OWASP API Top 10 vulnerability classifications
PHASE 7

Dynamic Runtime Instrumentation

dynamic_analysis.py

Injects Frida 16.x DBI scripts into the live Android process via ADB. Hooks javax.crypto.Cipher to extract symmetric encryption keys, intercepts Keystore aliases, captures SQLite runtime queries, and monitors cleartext sockets. Automatically uninstalls the target application upon completion.

Inputs: Live application process on connected ADB emulator/device Outputs: Runtime memory captures, hooked API calls, cryptographic trace logs
PHASE 8

RAG Vulnerability Mapping & LLM Triage

vulnerability_mapper.py

Executes multi-stage fuzzy deduplication, normalizes raw scanner signals against 34 ontology graph taxonomy edges, queries the 2,075-document Hybrid RAG knowledge base via BM25 + TF-IDF with Reciprocal Rank Fusion (k=60), and prompts the local Ollama LLM to verify control-flow reachability and eliminate false positives.

Inputs: Raw candidate findings from Phases 1–7 Outputs: Verified, RAG-grounded vulnerability findings with actionable code patches
PHASE 9

Automated Risk Scoring (CVSS v3.1)

risk_assessment.py

Calculates deterministic CVSS v3.1 vector equations across Base, Temporal, and Environmental metrics (AV, AC, PR, UI, S, C, I, A). Classifies findings into Critical, High, Medium, Low, and Informational severity tiers, enforcing deterministic noise suppression gates (τ = 0.80).

Inputs: Enriched vulnerability objects Outputs: CVSS scores, vector strings, severity tiers, noise suppression statistics
PHASE 10

Multi-Format Report Generation & Export

report_generator.py

Renders the complete audit through an interactive HTML5 Executive Dashboard using Jinja2 templates, while compiling machine-readable standard JSON reports containing granular code snippets, line numbers, CWE mappings, and drop-in Java/XML diffs.

Inputs: Final scored findings, app metadata, scan timeline Outputs: Downloadable HTML and standard JSON audit reports
